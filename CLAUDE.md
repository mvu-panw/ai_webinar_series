# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview
Static multi-page HTML/CSS/JS site for "Palo Alto Networks AI Security By Design" — a 6-page informational/demo microsite (Home, Agentic Endpoint Security, AI Gateway, AI Runtime Security, Frontier AI Defense, PHP2Shell Webinar). No build tools, no framework, no npm dependencies (one page loads `marked` from a CDN), no auth gate — every page is open. Open any `.html` file directly in a browser or serve with any static file server.

This site replaced an earlier "PANW Capture the Flags" event site (registration → menu → per-product CTF challenges → scoreboard); that flow, its `sessionStorage` auth guard, and its Apps Script-backed registration/scoring have all been removed. `ai_security_by_design.md` is the source spec this rebuild implements.

## Key Behaviors
- **No auth guard**: unlike the old CTF site, no page checks `sessionStorage` or redirects — every page is directly reachable.
- **No templating**: navbar/footer markup is duplicated in every HTML file. Edit all 6 files when updating shared layout.
- **Two embed styles in `assets/css/styles.css`** — only one is currently used: the `aspect-ratio` CSS property set directly on the embedded element (`aes.html`'s demo `<iframe>` inside `.embed-wrap`; `index.html`'s `.slideshow-frame` applies the same idea to its container) avoids the flicker that the older Storylane `padding-bottom` percentage-hack technique caused. If a future page embeds iframe content, copy the `aspect-ratio` pattern from these, not a padding-bottom trick.
- **Static-graphic link-out pattern**: `ai-gateway.html` and `ai-runtime-security.html` each use the same `.graphic-link` pattern instead of an iframe — a static image (`aspect-ratio` set inline per-image to match its real dimensions) wrapped in an `<a target="_blank">`, plus a matching `.btn.btn-primary` CTA below it linking to the same external URL. Copy this pattern (not an iframe) for a future page that should link out via a static graphic rather than embed live content.
- **Stylesheet cache-busting**: every page links `assets/css/styles.css?v=6` with the same version query string. Bump `?v=N` in all 6 HTML files together when editing `styles.css`, or GitHub Pages/browser caching can serve stale CSS to some pages and not others.
- **"Cross launch" vs. "embed"**: per `ai_security_by_design.md`, AES's Demo Page is an inline `<iframe>` embed; its Sandbox section is instead a `target="_blank"` link-out button — that distinction is intentional, not an inconsistency.
- **Site-wide nav**: each page's `.nav-links` lists the other 5 pages (the current page omits a link to itself), and the nav `site-title` always links to `index.html`. The nav link to `aes.html` is labeled "Endpoint and Identity Security" on every page, while the page's own `<title>`/`<h1>` say "Agentic Endpoint Security"; renaming that page means updating the nav label in the other 5 files too. On screens ≤600px the nav wraps (`flex-wrap` in the responsive block) since 5 links no longer fit on one line.
